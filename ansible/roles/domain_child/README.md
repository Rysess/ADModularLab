# Role: `child_dc`

Promotes the host into the first domain controller of a child domain beneath an
existing forest root. Applied to hosts with `role: child_dc`.

Creating the child establishes the parent-child trust automatically.

## Requirements

| Key | Value |
| --- | ----- |
| `os` | `windows` |
| `min_instance_type` | `t3.medium` |
| `requires_lab_role` | `dc` |

The computer name is set by the `Set Windows computer names` play in
`site.yml`, before this role runs.

## Variables

| Variable | Default | Meaning |
| -------- | ------- | ------- |
| `domain_child_domain` | `{{ domain_name }}` | Domain this host serves |
| `domain_child_parent_domain` | derived | That domain minus its first label |
| `domain_child_parent_host` | `dc_hosts_by_domain[parent]` | Resolved by domain, not by inventory order |
| `domain_child_admin_user` | `{{ child_dc_user }}@{{ parent }}` | Dedicated account, created by the `dc` role |
| `domain_child_admin_password` | `child_dc_password` | Generated by Terraform |
| `domain_child_parent_wait_timeout` | `1800` | Seconds to wait for LDAP on the parent |
| `domain_child_retries` / `_delay` | `3` / `60` | Retry budget for the promotion |

Consumed from Terraform: `domain_name`, `domain_netbios`, `dsrm_password`.

The host's `domain` is the domain the child serves. The parent follows from the
name, so `child.lab.local` is a child of `lab.local`.

## Does

1. Points DNS at the forest root.
2. Waits for TCP/389 on it.
3. Promotes with `microsoft.ad.domain_child`, which owns the reboot.
4. Repoints DNS at itself, then the forest root, then `::1`.
5. Waits for ADWS.

Creating a child domain needs Enterprise Admin. The `dc` role provisions
`svc_childdc` in the parent domain for exactly this, and only when the lab
holds a child of that domain; the built-in Administrator is not used.

## Footprint

4 GB minimum. Promotion and reboot take 5-10 minutes once the parent is up.
